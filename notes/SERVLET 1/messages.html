# 4️⃣ Filter (Before Servlet)

Filter intercepts the request before servlet execution.

package com.app;

import javax.servlet.*;
import javax.servlet.http.*;
import java.io.IOException;

public class AuthFilter implements Filter {

    public void init(FilterConfig config) {
        System.out.println("Filter Initialized");
    }

    public void doFilter(ServletRequest req,
                         ServletResponse res,
                         FilterChain chain)
            throws IOException, ServletException {

        HttpServletRequest request = (HttpServletRequest) req;

        System.out.println("Filter Executed Before Servlet");

        chain.doFilter(req, res);

        System.out.println("Filter Executed After Servlet");
    }

    public void destroy() {}
}

# 5️⃣ Servlet Implementation
11:01 
package com.app;

import javax.servlet.*;
import javax.servlet.http.*;
import java.io.*;

public class LoginServlet extends HttpServlet {

    public void init() throws ServletException {

        System.out.println("Servlet init() called");

        ServletConfig config = getServletConfig();

        String version = config.getInitParameter("version");

        System.out.println("Servlet Version : " + version);
    }

    protected void doPost(HttpServletRequest request,
                          HttpServletResponse response)
            throws ServletException, IOException {

        String username = request.getParameter("username");
        String password = request.getParameter("password");

        ServletContext context = getServletContext();

        String appName = (String) context.getAttribute("appName");

        if("admin".equals(username) && "123".equals(password)){

            HttpSession session = request.getSession();

            session.setAttribute("user", username);

            Cookie cookie = new Cookie("user", username);

            response.addCookie(cookie);

            RequestDispatcher rd =
                    request.getRequestDispatcher("home.jsp");

            rd.forward(request,response);

        }else{

            PrintWriter out = response.getWriter();

            out.println("<h3>Login Failed</h3>");
        }
    }

    public void destroy(){
        System.out.println("Servlet destroyed");
    }
}

# COOKIE MANAGEMENT :

In Java Servlets (for example when running on Apache Tomcat):

### 1️⃣ Session creation

When you write:

HttpSession session = request.getSession();


The servlet container:

1. Creates a session object in the server
2. Generates a unique Session ID

Example:

SessionID = A7F9B21C


Server stores internally:

A7F9B21C → { user=admin }


---

### 2️⃣ Servlet container automatically creates cookie

The container automatically sends this response header:

Set-Cookie: JSESSIONID=A7F9B21C


Browser stores it as a cookie.

You do not write any code for this.

---

### 3️⃣ Next request

Browser automatically sends:

Cookie: JSESSIONID=A7F9B21C


---

### 4️⃣ Servlet container reads cookie

The servlet container automatically:

1. Reads the cookie
2. Extracts JSESSIONID
3. Searches session map
4. Retrieves the session object

Internally:

A7F9B21C → { user=admin }


Then it returns the session when you call:

request.getSession()


---

# ✔️ So,

The servlet container automatically stores the session ID in a cookie 
called JSESSIONID.

Developers do not need to manually create or read this cookie.

The container automatically reads the JSESSIONID cookie from the request 
and retrieves the corresponding session object from the server memory.


---

# ✔️ Internal Working (Very Important)

Inside the server there is something like:

Session Map

JSESSIONID        Session Object
-----------------------------------------
A7F9B21C      →   {user=admin}
X82KD92M      →   {user=rahul}
KQ82JD91      →   {user=alex}


Browser only stores:

JSESSIONID=A7F9B21C


Actual data stays only in server.

---

# ✔️ Why Cookie is Needed

HTTP is stateless.

Without cookies:

Request 1 → login
Request 2 → profile


Server cannot know both requests are from the same user.

So cookie carries the session identifier.

---

# ✔️ One More Important Interview Question

Sometimes the interviewer asks:

"What happens if cookies are disabled?"

Then session works using:

URL Rewriting


Example:

/profile;jsessionid=A7F9B21C


Servlet automatically appends session id to URLs.

# ✔️ 

Session data is stored on the server, and the session ID that identifies
that session is stored in a cookie called JSESSIONID. The servlet
container automatically manages creating, sending, and reading this cookie.

The servlet container automatically creates and manages a cookie called JSESSIONID to maintain session tracking. Developers do not need to handle this cookie manually. If we want to store additional information in cookies, such as user preferences or last login time, we must explicitly create and add those cookies in the response.

=================

1. For the first request,

*. Web container create instance of servlet using newInstance() method.

web.xml file tags definition :
=======================
1. <display-name> :
The optional display-name element specifies the Web application display name, a short name that can be displayed by GUI tools. Currently, this element is not used by WebLogic Server.

2. <description>
Description about the Application or Servlet.

3. <welcome-file-list>
It contains set of <welcome-file> tags. In any web application index.html acts as default welcome file.If index.html is not available then index.jsp acts as default welcome file.

4. <servlet>
Servlet tag contains the information about servlet such as,

4.1 <servlet-name> (Logical name used for Servlet mapping)
4.2 <servlet-class> (Fully qualified class name of Servlet)
4.3 <jsp-file> (
4.4 <load-on-starup> (At the time of first request servlet class will be loaded and servlet object will be created followed by init() method execution.Finally service() method will be called. But for second request onwards only service() method will be called.
Because of this the processing time of first request is more when compared with other requests.
To overcome this problem we should go for <load-on-startup>. If we configured <load-on-startup> then servlet class loading,servlet instantiation and execution of init() method will be performed at the time of server start up or at the time of application deployment. For the first request also only service() method will be called. The values must be positive integer. Based on values, each servlet will be loaded.)
4.5 <init-param> (Servlet configuration information. This information specific for enclosing servlet.)

5. <servlet-mapping>
This tag is used to map servlet class with url-pattern.
5.1 <servlet-name> (Logical name of servlet)
5.2 <url-pattern> (url-pattern of the servlet or jsp file)

6. <context-param>
This holds the application level information.

7. <filter>
This tag is quite similar to the servlet tag. The only difference is "the name servlet is replaced by filter in tag names".
Under this tag, all tags such as <filter-name>, <filter-class>, <filter-mapping>, <url-pattern> have same meaning.

8.3 <servlet-name>
Adding filter for servlet name rather attach it for specific url pattern.
8.4 <dispatcher>
A servlet can get the request in one of the following 4 ways.
1. A Request Directly from Browser(REQUEST)
2. By RequestDispatcher's forward() call(FORWARD)
3. By RequestDispatcher's include() call(INCLUDE)
4. By Error Page Call(ERROR)
By default Filter concept is applicable only for direct end user REQUEST and not applicable for RD's forward,include calls and error page calls.
If we want to extend for remaining cases also then we should go for <dispatcher> tag.

9. <error-page>
Configuring error page for particular servlet or jsp file.
9.1 <exception-type> (If Particular exception arise, then this error-page will be shown)
9.2 <error-code> (If particular error-code arise, then this error-page will be shown)
9.3 <location> (Location of error-page.)

10. <session-timeout>
Sets the number of minutes, session will active. (-ve values indicates the session never expires).

Parameters and Attributes :-
========================
Parameters are available in html/jsp forms and <init-param> and <context-param> tags.
So, ServletRequest, ServletContext, ServletConfig contains parameters.

The methods are, 
1. request.getParameter()
2. servletContext.getInitParameter()
3. servletConfig.getInitParameter()

Parameters are unchangeable values. So to have changeable values and to share data across the servlets or pages, we need an alternative. Yes, Attributes are the alternatives.

Attributes can managed in 3 scopes in servlet and 4 scopes in jsp.
They are,
1. request scope
2. session scope
3. Application scope (Context)

Methods are,
1. request.setAttribute(), request.getAttribute()
2. session.setAttribute(), session.getAttribute()
3. context.setAttribute(), context.getAttribute()

Difference between parameters and attributes :
========================================
i) Attributes are changeable. Whereas, Parameters are unchangeable.
ii) Return type of Paramteres are string. Return type of Attributes are Object.
iii) We can only store String type in Parameter. We can store object type in Attributes.

Moving from one page/Servlet to an other :-
=====================================
1. request.getRequestDispatcher().forward("url-pattern");
2. context.getRequestDispatcher().forward("url-pattern");
3. response.sendRedirect("location");

Difference Between RequestDispatcher of Request and Context :
======================================================
1. By using request's RequestDispatcher we can only forward to servlet belongs to same application.
2. But by using context's RequestDispatcher we can forward to servlet belongs to outside of the application, but inside the same server.
3. We can use sendRedirect() method to move to another servlet/page on another server.

Filter Interface :-
=============
Contains 3 methods :-
1. init(servletconfig)
2. doFilter(HSReq, HSRes, FilterChain)
3. destroy()

NOTE : doFilter() contains extra arguement, which is FilterChain.

After doFilter() method, the request don't move to Servlet/Jsp automatically. We have to call filterChain.doFilter(req, res).

Once the JVM executes the filterChain.doFilter() method, then it looks for any other Filter classes configured for particular url pattern or request servlet. If so, then request forwarded to next filter class. Otherwise, request goes to Servlet object.

Similar to Servlet, All the 3 methods called by the web container. doFilter() method is called when request made to configured servlet or url pattern.

Session and Cookies :-
===================

Session :
========
*. Whenever browser sends a request to server,If server wants to remember client information for the future purpose,then Server will create Session object and store required information in the form of attributes.Server sends the corresponding sessionid as the part of response.For this server will use setCookie response header.

*. Browser will retrieve that session id and will send with every consecutive request to the server.For this browser will use cookie request header.

*. Hence session id exchanging b/w client and server with setCookie response header and cookie request header.

HttpSession s = req.getSession();

1. public boolean isNew()
To check whether the session object is newly created or not
2. public void invalidate()
to expire a session forcefully
3. public void setMaxInactiveInterval(int seconds)
To set session timeout for a particular session object
4. public int getMaxInactiveInterval()
Returns the session timeout value in seconds
5. public String getId()
Returns session id

Cookie :
=======
Browser stores that cookie in the local file system and sends to the server with every consecutive request.By accessing that cookie server can able to remember client information.

Cookie c = new Cookie("key", "value")
resp.addCookie(c);

1. public String getName()
returns the name of the Cookie
2. public String getValue()
returns the value of the Cookie
3. public int getMaxAge()
Returns the max age of the Cookie in seconds.
