# The Story of How Spring Boot Works

---

# 1️⃣ The Problem with Traditional Spring Applications

Before Spring Boot, creating a project using the Spring Framework required a lot of setup.

Developers had to:

* Add many dependencies manually
* Configure XML files
* Configure server deployment
* Configure database
* Configure security
* Configure MVC

Example configuration files:

web.xml
applicationContext.xml
dispatcher-servlet.xml


Even for a simple REST API, developers wrote a lot of configuration code.

This slowed down development.

---

# 2️⃣ Spring Boot's Goal

Spring Boot was created to:

> Make Spring applications easy to build, configure, and run.

Spring Boot mainly provides:

1️⃣ Auto Configuration
2️⃣ Starter Dependencies
3️⃣ Embedded Servers
4️⃣ Production-ready features

---

# 3️⃣ Creating a Spring Boot Application

A Spring Boot application starts with a main class.

Example:

@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}


What happens here?

main()
   ↓
SpringApplication.run()
   ↓
Spring Container starts
   ↓
Application starts


---

# 4️⃣ What is @SpringBootApplication?

This is the main annotation of Spring Boot.

It combines three annotations:

@SpringBootApplication
     ↓
@Configuration
@ComponentScan
@EnableAutoConfiguration


Meaning:

```
| Annotation | Purpose |
| -------------------------- | ------------------------------------ |
| @Configuration | defines configuration |
| @ComponentScan | finds beans |
| @EnableAutoConfiguration | automatically configures application |
```
---

# 5️⃣ Starter Dependencies

Spring Boot introduces Starter Dependencies.

These are dependency bundles that bring everything needed for a feature.

Example:

spring-boot-starter-web


This automatically includes:

* Spring MVC
* Jackson
* Embedded server
* Validation
* Logging

Instead of adding many dependencies manually.

Managed using Apache Maven.

Example:

<dependency>
 <groupId>org.springframework.boot</groupId>
 <artifactId>spring-boot-starter-web</artifactId>
</dependency>


---

# 6️⃣ Auto Configuration

Spring Boot automatically configures components based on the dependencies present.

Example:

If spring-boot-starter-web is added:

Spring Boot automatically configures:

* DispatcherServlet
* Jackson JSON converter
* REST controller support
* Embedded server

So developers write less configuration.

---

# 7️⃣ Embedded Server

Traditional Spring apps required deploying a WAR to a server like Apache Tomcat.

Spring Boot includes an embedded server.

Example servers:

* Apache Tomcat
* Jetty
* Undertow

So the application can run directly:

java -jar application.jar


No external server setup needed.

---

# 8️⃣ Configuration using application.properties

Spring Boot simplifies configuration using a properties file.

Example:

server.port=8081
spring.datasource.url=jdbc:mysql://localhost:3306/app
spring.datasource.username=root


Instead of complex XML configuration.

Files supported:

application.properties
application.yml


---

# 9️⃣ Packaging and Running

Spring Boot applications are packaged as executable JAR files.

Using Apache Maven:

mvn clean package


Output:

application.jar


Run the application:

java -jar application.jar


This starts:

Spring Boot
     ↓
Spring Container
     ↓
Embedded Server
     ↓
Application Ready

# 1️⃣ What @Configuration Means

@Configuration tells the Spring Framework container:

> "This class contains bean definitions that should be managed by Spring."

Example:

@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}


What happens:

Spring starts
     ↓
Finds @Configuration class
     ↓
Executes @Bean methods
     ↓
Registers returned objects as beans


So:

Purpose of `@Configuration`

* Defines manual bean configuration
* Used for application-specific setup

---

# 2️⃣ What @EnableAutoConfiguration Means

@EnableAutoConfiguration tells Spring Boot:

> "Automatically configure beans based on the dependencies present in the classpath."

Example:

If your project has:

spring-boot-starter-web


Spring Boot automatically configures:

* DispatcherServlet
* Jackson
* Embedded Tomcat
* Message converters
* MVC configuration

You don't write any configuration.

---

# 3️⃣ What Problem @EnableAutoConfiguration Solves

Before Spring Boot, developers had to configure everything manually.

Example for Spring MVC:

You had to configure:

DispatcherServlet
ViewResolver
MessageConverters
HandlerMapping
HandlerAdapter


Example XML (old Spring):

<mvc:annotation-driven/>
<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver"/>


With Spring Boot:

Add spring-boot-starter-web
      ↓
Auto configuration runs
      ↓
Everything configured automatically


So it solves:

| Traditional Spring | Spring Boot |
| -------------------- | ----------------------- |
| manual configuration | automatic configuration |
| many XML files | almost none |
| longer setup | quick startup |

---

# 4️⃣ How @EnableAutoConfiguration Works Internally

This is the real magic of Spring Boot.

@EnableAutoConfiguration loads configuration classes listed in:

META-INF/spring.factories


(or in newer versions)

META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports


Example entries:

org.springframework.boot.autoconfigure.web.servlet.DispatcherServletAutoConfiguration
org.springframework.boot.autoconfigure.jackson.JacksonAutoConfiguration
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration


When the application starts:

Spring Boot starts
        ↓
@EnableAutoConfiguration triggers
        ↓
Reads auto configuration classes
        ↓
Checks classpath dependencies
        ↓
Applies configuration conditionally


Example condition:

@ConditionalOnClass(DispatcherServlet.class)


Meaning:

If DispatcherServlet exists in classpath
        ↓
Enable MVC configuration


---

# 5️⃣ Difference Between @Configuration and @EnableAutoConfiguration

| Feature | @Configuration | @EnableAutoConfiguration |
| ------------- | --------------------- | -------------------------------- |
| Purpose | Define beans manually | Automatically configure beans |
| Who writes it | Developer | Spring Boot |
| Control | Full control | Automatic setup |
| Example | Custom ObjectMapper | Auto-configure DispatcherServlet |

Example:

Manual configuration:

@Configuration
class AppConfig {

    @Bean
    public DataSource dataSource(){
        return new HikariDataSource();
    }
}


Auto configuration:

Add spring-boot-starter-data-jpa
        ↓
Spring Boot auto creates DataSource


---

# 6️⃣ Why @SpringBootApplication Includes @Configuration

@SpringBootApplication is defined as:

@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan


And:

@SpringBootConfiguration
      ↓
@Configuration


Meaning:

The main class itself becomes a configuration class.

Example:

@SpringBootApplication
public class App {

    public static void main(String[] args) {
        SpringApplication.run(App.class,args);
    }

    @Bean
    public ObjectMapper mapper(){
        return new ObjectMapper();
    }
}


Even though most people don't write beans here, they can.

# 7️⃣ Why Spring Boot Needs a Configuration Class at Startup

Spring needs one root configuration class to start the application context.

When this runs:

SpringApplication.run(App.class)


Spring treats App.class as the primary configuration source.

Flow:

Application starts
       ↓
SpringApplication.run()
       ↓
Load App.class
       ↓
Recognize @Configuration
       ↓
Start Spring container
       ↓
Scan components
       ↓
Apply auto configuration


---

# 8️⃣ Why Not Remove @Configuration from @SpringBootApplication?

Because the main class must act as:

Primary configuration class


Without it:

* Spring wouldn't know where to start configuration
* Bean definitions in the main class wouldn't work

---

# 9️⃣ Complete Startup Flow

Full internal flow:

Main method runs
       ↓
SpringApplication.run()
       ↓
Load main class (@SpringBootApplication)
       ↓
@Configuration registers beans
       ↓
@ComponentScan finds components
       ↓
@EnableAutoConfiguration loads auto configs
       ↓
Conditions checked (@ConditionalOnClass)
       ↓
Required beans created
       ↓
Application context ready
       ↓
Embedded server starts

# 🔟 Simple Analogy

Think of Spring Boot like this:

@Configuration
    = Custom instructions from developer

@EnableAutoConfiguration
    = Default instructions from Spring Boot


Spring merges both.
