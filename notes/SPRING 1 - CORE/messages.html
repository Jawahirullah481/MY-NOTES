# The Story of How Spring Framework Core Works

## 1️⃣ The Problem with Traditional Java Applications

In traditional Java applications:

class OrderService {
    PaymentService paymentService = new PaymentService();
}


Problems:

* Classes create their own dependencies
* Code becomes tightly coupled
* Hard to test
* Hard to maintain

If PaymentService changes, OrderService must also change.

Developers needed a solution.

---

# 2️⃣ Spring's Solution — Inversion of Control (IoC)

Spring introduced the concept of Inversion of Control.

Idea:

> Instead of objects creating their dependencies, Spring creates and manages them.

Example:

class OrderService {
    PaymentService paymentService;
}


Spring will provide the dependency.

This principle is called:

Dependency Injection (DI).

---

# 3️⃣ Spring Container – The Heart of Spring

The Spring Container manages the lifecycle of objects.

Main container implementation:

* Spring ApplicationContext

Responsibilities:

* Create objects
* Inject dependencies
* Manage lifecycle
* Manage configuration

Flow:

Application starts
        ↓
Spring Container starts
        ↓
Beans are created
        ↓
Dependencies are injected
        ↓
Application runs


---

# 4️⃣ What is a Spring Bean?

A Spring Bean is simply:

> An object created and managed by the Spring Container.

Example:

@Service
class PaymentService {}


Here PaymentService becomes a Spring Bean.

Spring stores it inside the container.

---

# 5️⃣ How Beans Are Created

Spring must know which classes to create as beans.

We mark them using annotations:

| Annotation | Purpose |
| ------------- | -------------- |
| @Component | Generic bean |
| @Service | Business logic |
| @Repository | Database layer |
| @Controller | Web layer |

All of them are specializations of `@Component`.

Example:

@Service
class PaymentService {}


Spring scans the class and registers it as a bean.

---

# 6️⃣ Component Scanning

Spring automatically scans packages for beans.

Enabled using:

@ComponentScan


Spring looks for:

@Component
@Service
@Repository
@Controller


and registers them as beans.

---

# 7️⃣ Dependency Injection

Now Spring injects dependencies between beans.

Example:

@Service
class OrderService {

    @Autowired
    PaymentService paymentService;

}


Here Spring injects the PaymentService bean into OrderService.

This is called Dependency Injection.

---

# 8️⃣ Types of Dependency Injection

There are three types.

### 1️⃣ Field Injection

@Autowired
PaymentService paymentService;


Simple but not recommended.

---

### 2️⃣ Setter Injection

@Autowired
public void setPaymentService(PaymentService paymentService){
    this.paymentService = paymentService;
}


---

### 3️⃣ Constructor Injection (Best)

private final PaymentService paymentService;

public OrderService(PaymentService paymentService){
    this.paymentService = paymentService;
}


Advantages:

* Dependency is mandatory
* Easier unit testing
* Supports immutability

---

# 9️⃣ When @Bean Is Needed

Sometimes we need to create beans for third-party classes.

Example:

@Configuration
class AppConfig {

    @Bean
    public ObjectMapper objectMapper(){
        return new ObjectMapper();
    }

}


Now Spring manages this object as a bean.

# 1️⃣1️⃣ Configuration Class

Spring configuration is written using:

Example:

# Final 5-Line Summary (Best for Interviews)

> Spring Core provides the IoC container that manages application objects called beans. These beans are created, configured, and wired together by the Spring container using dependency injection. Beans can be defined using annotations like @Component, @Service, or through @Bean methods inside configuration classes. The container handles the lifecycle of these beans from creation to destruction.
