# The Story of How Spring MVC Handles a Request

Imagine a user opening a website.

Example request:

GET /users


This request travels through the Spring application.

---

# 1️⃣ Client Sends Request

The user (browser / frontend / Postman) sends a request to the server.

Example:

http://localhost:8080/users


The request first reaches the web server.

In Spring Boot this server is usually:

* Apache Tomcat (embedded)

Flow so far:

Client
   ↓
Tomcat Server


---

# 2️⃣ DispatcherServlet – The Front Controller

The request is forwarded to the DispatcherServlet.

DispatcherServlet is the heart of Spring MVC.

It acts as a Front Controller.

Meaning:

> All incoming HTTP requests first go to DispatcherServlet.

Flow:

Client
   ↓
Tomcat
   ↓
DispatcherServlet


DispatcherServlet’s job is to:

* Receive request
* Find correct controller
* Call the controller
* Return response

---

# 3️⃣ Handler Mapping – Finding the Correct Controller

Now DispatcherServlet must determine:

> Which controller method should handle this request?

Spring uses HandlerMapping for this.

Example controller:

@RestController
public class UserController {

    @GetMapping("/users")
    public List<User> getUsers(){
        return userService.getAllUsers();
    }

}


HandlerMapping sees:

GET /users


and maps it to:

UserController.getUsers()


Flow:

DispatcherServlet
       ↓
HandlerMapping
       ↓
Correct Controller Found


---

# 4️⃣ Controller Handles Request

Now the controller method executes.

Controller's job:

* Receive request
* Call business logic
* Return response

Example:

@GetMapping("/users")
public List<User> getUsers(){
    return userService.getAllUsers();
}


Flow:

DispatcherServlet
      ↓
Controller


---

# 5️⃣ Service Layer – Business Logic

Controllers usually call service classes.

Example:

@Service
public class UserService {

    public List<User> getAllUsers(){
        return userRepository.findAll();
    }

}


Purpose:

* Business logic
* Application rules
* Transaction handling

Flow:

Controller
     ↓
Service


---

# 6️⃣ Repository Layer – Database Access

Service classes call repository classes.

Example:

@Repository
public interface UserRepository extends JpaRepository<User,Long> {}


Responsibilities:

* Database queries
* Data persistence

Flow:

Service
   ↓
Repository
   ↓
Database


---

# 7️⃣ Data Travels Back

After fetching data:

Database
   ↓
Repository
   ↓
Service
   ↓
Controller


The controller returns the result.

Example:

return users;


---

# 8️⃣ Response Conversion (JSON)

Spring automatically converts Java objects to JSON using:

* Jackson

Example Java object:

User { id:1, name:"John" }


Converted to:

{
 "id":1,
 "name":"John"
}


This is handled by HttpMessageConverters.

---

# 9️⃣ Response Sent Back to Client

Finally:

Controller Response
      ↓
DispatcherServlet
      ↓
Tomcat
      ↓
Client receives JSON


---

# Complete Request Flow

Client
   ↓
Tomcat Server
   ↓
DispatcherServlet
   ↓
HandlerMapping
   ↓
Controller
   ↓
Service
   ↓
Repository
   ↓
Database

Response Flow

Database
   ↓
Repository
   ↓
Service
   ↓
Controller
   ↓
DispatcherServlet
   ↓
Client

# MVC Components Explained

| Component  | Responsibility         |
| ---------- | ---------------------- |
| Model      | Application data       |
| View       | UI (HTML / JSP / JSON) |
| Controller | Handles requests       |


In REST APIs:

View = JSON response


---

# Important Spring MVC Annotations

| Annotation        | Purpose              |
| ----------------- | -------------------- |
| `@Controller`     | Web controller       |
| `@RestController` | REST API controller  |
| `@RequestMapping` | Map URL              |
| `@GetMapping`     | Handle GET request   |
| `@PostMapping`    | Handle POST request  |
| `@RequestBody`    | Read JSON request    |
| `@PathVariable`   | Read path parameter  |
| `@RequestParam`   | Read query parameter |

# Interview Answer (Spring MVC)

> Spring MVC is a web framework based on the Model-View-Controller pattern. It uses DispatcherServlet as the front controller to receive all HTTP requests, which are then mapped to controller methods. Controllers process requests, interact with services and repositories, and return responses that are converted into JSON or views.

---

# Key Concept to Remember

Spring MVC works using the Front Controller Pattern.

The DispatcherServlet manages the entire request lifecycle.
