# Maven Notes (Complete Flow)

## 1. What is Maven

Maven is a build automation and dependency management tool used mainly for Java projects.

Main purposes:

* Manage project dependencies
* Compile code
* Run tests
* Package application (JAR/WAR)
* Deploy application

Before Maven, developers manually downloaded JAR files and added them to the project.

---

# 2. Maven Project Structure (Standard Layout)

Maven enforces a standard directory structure.

project-name
│
├── pom.xml
│
├── src
│   ├── main
│   │   ├── java        -> Application source code
│   │   ├── resources   -> properties, xml files
│   │   └── webapp      -> web files (jsp, html, css)
│   │
│   └── test
│       ├── java        -> test classes
│       └── resources
│
└── target              -> compiled output


Important:

target/ directory is generated automatically after build.

---

# 3. POM File (Project Object Model)

The pom.xml file is the heart of Maven.

It contains:

* project information
* dependencies
* plugins
* build configuration

Example:

<project>

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.company</groupId>
    <artifactId>demo-project</artifactId>
    <version>1.0</version>

</project>


---

# 4. Important Maven Coordinates

Every Maven project is uniquely identified by:

| Element | Meaning |
| ---------- | ------------------ |
| groupId | Organization name |
| artifactId | Project name |
| version | Version of project |

Example:

groupId: com.google
artifactId: gson
version: 2.10


Unique ID:

com.google:gson:2.10


---

# 5. Maven Repositories

Repositories store libraries (JAR files).

Location:

When Maven downloads a dependency it stores it here.

---

### 2. Central Repository

Default public repository.

Example libraries:

* Spring
* Hibernate
* Jackson

Managed by
Apache Maven

URL:

https://repo.maven.apache.org/maven2


---

### 3. Remote Repository

Company/private repository.

Examples:

* Nexus
* Artifactory

---

# 6. Maven Dependency

Dependencies are external libraries required by the project.

Example:

<dependencies>

    <dependency>
        <groupId>com.fasterxml.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
        <version>2.17.0</version>
    </dependency>

</dependencies>


Example usage in frameworks like
Spring Framework.

---

# 7. Dependency Scope

Scope determines where dependency is available.

| Scope | Available |
| -------- | --------------------- |
| compile | everywhere |
| provided | provided by container |
| runtime | runtime only |
| test | only during testing |
| system | local jar |

Example:

<scope>test</scope>


Used for libraries like
JUnit.

---

# 8. Maven Build Lifecycle

A lifecycle is a sequence of build phases.

3 built-in lifecycles:

| Lifecycle | Purpose |
| --------- | ---------------------- |
| clean | remove previous build |
| default | build project |
| site | generate documentation |

If you run install, Maven executes all previous phases automatically.

# Maven Main Build Phases Notes

Maven follows a build lifecycle, where each phase performs a specific task in building the project.

Important phases:

validate → compile → test → package → install → deploy


Important rule:

> When a phase is executed, all previous phases run automatically.

Example:

mvn package


actually runs:

validate → compile → test → package


---

# 1️⃣ validate Phase

### Purpose

Checks whether the project structure and configuration are correct before building.

### What Maven checks

* pom.xml syntax
* required project metadata
* dependency configuration
* project structure

Example required fields in pom.xml:

<groupId>com.example</groupId>
<artifactId>demo</artifactId>
<version>1.0</version>


If any configuration is wrong:

BUILD FAILURE


No compilation happens yet.

---

# 2️⃣ compile Phase

### Purpose

Compiles the main source code of the project.

Source folder:

src/main/java


Compiled classes generated in:

target/classes


Example:

UserService.java


becomes:

UserService.class


If compilation errors exist:

BUILD FAILURE


and next phases will not execute.

---

# 3️⃣ test Phase

### Purpose

Runs unit tests written for the application.

Test source folder:

src/test/java


Testing frameworks commonly used:

* JUnit
* TestNG

Compiled test classes stored in:

target/test-classes


If any test fails, Maven stops execution.

Example output:

Tests run: 10, Failures: 1
BUILD FAILURE


Next phases like package will not run.

---

# 4️⃣ package Phase

### Purpose

Creates the distributable artifact of the application.

Depending on project type:

| Packaging Type | Output                 |
| -------------- | ---------------------- |
| jar            | Java application       |
| war            | Web application        |
| ear            | Enterprise application |


Output location:

target/


Example:

target/demo-1.0.jar


or

target/demo-1.0.war


---

# 5️⃣ install Phase

### Purpose

Stores the packaged artifact in the local Maven repository.

Local repository location:

~/.m2/repository


Example stored file:

~/.m2/repository/com/example/demo/1.0/demo-1.0.jar


### Why install is needed

So other projects in your machine can use it as a dependency.

Example dependency:

<dependency>
  <groupId>com.example</groupId>
  <artifactId>demo</artifactId>
  <version>1.0</version>
</dependency>


---

# 6️⃣ deploy Phase

### Purpose

Uploads the artifact to a remote repository.

Used in team environments.

Remote repositories examples:

* Nexus Repository Manager
* JFrog Artifactory

Example flow:

Developer builds artifact
        ↓
Artifact deployed to remote repository
        ↓
Other developers download it as dependency


Used mostly in CI/CD pipelines.

# Difference Between JAR and WAR

Both JAR and WAR are archive formats used to package Java applications using build tools like Apache Maven.

---

# 1️⃣ JAR (Java Archive)

### Definition

JAR stands for Java ARchive.
It is used to package Java classes, resources, and libraries into a single file.

### Structure

myapp.jar
 ├── META-INF/
 │     └── MANIFEST.MF
 └── com/
       └── example/
            └── App.class


### Contains

* compiled .class files
* configuration files
* resource files
* libraries

### Usage

* Java standalone applications
* reusable libraries
* microservices

Applications built with Spring Boot are usually packaged as JAR.

### Execution

java -jar myapp.jar


Spring Boot JAR files contain an embedded server like:

* Apache Tomcat
* Jetty
* Undertow

So they can run independently.

---

# 2️⃣ WAR (Web Archive)

### Definition

WAR stands for Web ARchive.
It is used to package Java web applications.

### Structure

myapp.war
 ├── index.jsp
 ├── css/
 ├── js/
 └── WEB-INF
      ├── web.xml
      ├── classes/
      └── lib/


### Contains

* JSP files
* HTML
* CSS
* JavaScript
* servlets
* compiled classes
* dependency libraries

### Usage

Traditional Java web applications.

WAR files are deployed into web servers such as:

* Apache Tomcat
* WildFly
* GlassFish

### Deployment

copy myapp.war → tomcat/webapps


The server extracts and runs it.

---

# 3️⃣ Key Differences

| Feature         | JAR                         | WAR                      |
| --------------- | --------------------------- | ------------------------ |
| Meaning         | Java Archive                | Web Archive              |
| Purpose         | Java application or library | Web application          |
| Server required | No                          | Yes                      |
| Contains        | Java classes and resources  | Web files + Java classes |
| Structure       | Simple                      | Contains WEB-INF         |
| Execution       | `java -jar`                 | Deploy to web server     |

---

# 4️⃣ Modern Usage

Earlier Java web applications were packaged as WAR and deployed to servers like Apache Tomcat.

Modern applications built with Spring Boot usually use JAR packaging because they contain an embedded server and run independently.

---

# 5️⃣ Interview Short Answer

> JAR files package Java classes and libraries and can run as standalone applications. WAR files package web applications containing JSP, HTML, and servlets and must be deployed in a web server like Tomcat.

# 1️⃣ Traditional Deployment (WAR + External Server)

Traditional Spring or Java web applications are packaged as WAR files and deployed into an external server like Apache Tomcat.

## Flow

Developer → Build WAR → Deploy to Server → Server runs application


---

## Step-by-Step Deployment Process

### 1. Build the WAR file

Using Apache Maven:

mvn clean package


This generates:

target/application.war


---

### 2. Stop the application server

Stop the running Tomcat server.

Example:

shutdown.sh


Or kill the process:

ps -ef | grep tomcat
kill <PID>


---

### 3. Remove the old WAR

Delete the existing deployed file.

tomcat/webapps/old-app.war
tomcat/webapps/old-app/


---

### 4. Copy the new WAR

Copy the generated WAR file into:

tomcat/webapps/


---

### 5. Start the server

Start Apache Tomcat again.

startup.sh


---

### 6. Tomcat Deployment Process

Tomcat will:

1. Detect the WAR file
2. Extract the WAR
3. Load libraries from WEB-INF/lib
4. Load classes from WEB-INF/classes
5. Start the web application

---

## WAR File Structure

app.war
│
├── index.jsp
├── css/
├── js/
└── WEB-INF
     ├── web.xml
     ├── classes
     └── lib
          spring.jar
          jackson.jar
          mysql.jar


---

# 2️⃣ Spring Boot Deployment (Executable JAR)

Applications built with Spring Boot are packaged as executable JAR files containing an embedded server (usually Apache Tomcat).

---

## Flow

Developer → Build JAR → Run JAR → Embedded Server Starts


---

## Step-by-Step Deployment Process

### 1. Build the JAR

Using Apache Maven:

mvn clean package


Output:

target/application.jar


---

### 2. Stop the running application

Find the running process.

ps -ef | grep application


Stop it.

kill <PID>


---

### 3. Replace the JAR

Copy the new JAR file to the server.

Example:

/apps/application.jar


---

### 4. Start the application

Run the JAR.

java -jar application.jar


---

### 5. Application Startup

When the JAR runs:

1. Spring Boot starts
2. Embedded Tomcat starts
3. Application context initializes
4. REST endpoints become available

---

## Spring Boot JAR Structure

application.jar
│
├── BOOT-INF
│    ├── classes
│    └── lib
│         spring.jar
│         jackson.jar
│         mysql.jar
│
└── org/springframework/boot/loader

# 3️⃣ Deployment Comparison

| Feature           | Traditional WAR    | Spring Boot JAR     |
| ----------------- | ------------------ | ------------------- |
| Packaging         | WAR                | Executable JAR      |
| Server            | External server    | Embedded server     |
| Deployment        | Copy WAR to server | Run JAR             |
| Server management | Manual             | Application-managed |
| Restart           | Restart server     | Restart application |
| Complexity        | Higher             | Simpler             |

# 5️⃣ Interview Answer (Short)

How do you deploy a traditional WAR vs Spring Boot application?

> In traditional applications we build a WAR file and deploy it to an external server like Tomcat. The server extracts the WAR and runs the application.
> In Spring Boot we generate an executable JAR containing an embedded server, and we simply start the application using java -jar.
