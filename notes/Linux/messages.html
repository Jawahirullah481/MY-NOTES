You successfully connected to the Linux server.

To answer these questions, you first need to understand how Linux organizes everything.

════════════════════════════════════

## 🏙 Think of Linux as a City

Imagine Linux is a well-planned city.

Every place has a specific purpose.

🏙 Linux City

        /
        │
 ┌──────┼───────────────────────┐
 │      │      │      │         │
home    etc    var    usr      opt
 │      │      │      │         │
Users  Settings Logs Programs Applications


Instead of creating folders anywhere,

Linux follows a standard directory structure.

Because of this, almost every Linux server looks familiar.

════════════════════════════════════

## 🏠 The Root Directory (/)

Everything in Linux starts from one directory:

/


This is called the Root Directory.

Don't confuse it with the root user**—they are different.

Think of `/` as the root of a tree.

```text
🌳

/
/ | \
/ | \
home etc var
```

Or as the main entrance to the Linux city.

Unlike Windows:

```text
C:\

D:\

E:\
```

Linux has only **one starting point:

/


════════════════════════════════════

## 🤔 Why Doesn't Linux Have C: and D: Drives?

Windows separates storage into different drives.

C:\

D:\

E:\


Linux treats everything as one filesystem.

Even if you add another hard disk, Linux mounts it as another directory.

Example:

/

├── home

├── var

├── etc

└── data


This makes Linux flexible and consistent.

════════════════════════════════════

These are the directories every backend developer should know.

This is a special directory.

Think of it as Linux's live dashboard.

This directory contains the files needed to start Linux.

/

pwd

$ pwd

> "I am currently inside `/home/ubuntu`."

💡 Production habit: Before running commands that modify or delete files, checking pwd can prevent mistakes.

## 🛣 Absolute Path vs Relative Path

This is an important concept.

### 🌍 Absolute Path

An absolute path starts from /.

Example:

/opt/payment-service/logs


It gives the complete address.

No matter where you currently are, this path points to the same location.

cd /opt/payment-service/logs


---

### 🏠 Relative Path

A relative path starts from your current location.

Suppose you're already here:

/opt/payment-service


And logs is inside it.

You can simply use:

cd logs


instead of:

cd /opt/payment-service/logs


Because Linux starts from where you currently are.

### 🧠 Easy Rule

Starts with /
      ↓
🌍 Absolute Path

Doesn't start with /
      ↓
📍 Relative Path


════════════════════════════════════

Now:

payment-service

├── app.jar

└── backup


mkdir means:

* `cd` → Changes directory / goes home when used without an argument.
* `cd ..` → Moves to the parent directory.
* `mkdir` → Creates a directory.
* Absolute Path → Complete path starting from /.
* Relative Path → Path based on the current directory.

🚀 Part 3: File Operations - Creating, Copying, Moving & Deleting Files Safely

════════════════════════════════════

You need to understand how Linux handles files.

════════════════════════════════════

## 🏗 Everything Is a File

A Spring Boot application may look like:

📁 payment-service

├── app.jar
├── application.yml
├── logs/
└── backup/


Linux treats different types of data as files:

📄 Text files
☕️ JAR files
📷 Images
📦 ZIP files
⚙️ Configuration files


So the commands we learn here work with almost any type of file.

════════════════════════════════════

## 📄 `touch` → Create a File

To create an empty file:

touch notes.txt


Now:

notes.txt


You can also create a configuration file:

touch application-test.yml


💡 Important: touch was originally designed to update a file's timestamp. If the file doesn't exist, it creates it.

════════════════════════════════════

## 📋 `cp` → Copy a File

Before replacing the current JAR, create a backup:

cp app.jar backup/app.jar


Now:

payment-service

├── app.jar
└── backup
    └── app.jar


The original file still exists.

cp
↓
Copy

Original + Copy


💼 Real Project

You might create a versioned backup:

cp app.jar backup/app-29-Jul.jar


If the new deployment fails, the old JAR can be restored.

════════════════════════════════════

## 📁 `cp -r` → Copy a Directory

Suppose you have:

config/

├── application.yml
├── database.yml
└── security.yml


To copy the entire directory:

cp -r config backup/


-r means:

> Recursive → Copy the directory and everything inside it.

════════════════════════════════════

## 🚚 `mv` → Move a File

Suppose a new JAR is in your current directory:

new-app.jar


Move it to the application folder:

mv new-app.jar /opt/payment-service/


The file is removed from its old location and appears in the new location.

Old Location
    ↓
new-app.jar
    ↓
   mv
    ↓
/opt/payment-service/new-app.jar


════════════════════════════════════

## ✏️ `mv` → Rename a File

The same command is used for renaming.

mv application.properties application-prod.properties


Now:

application-prod.properties


The file wasn't copied.

Only its name changed.

### 🧠 Why?

Moving means:

> Change the file's location.

Renaming means:

> Change the file's name.

Both are handled by mv.

════════════════════════════════════

## 🗑 `rm` → Delete a File

To delete a file:

rm old-app.jar


⚠️ Linux normally doesn't move deleted files to a Recycle Bin.

So treat rm carefully.

════════════════════════════════════

## 📁 `rmdir` → Delete an Empty Directory

If a directory is empty:

rmdir temp/


It will be deleted.

If it contains files, rmdir will refuse.

════════════════════════════════════

## 💣 `rm -rf` → Delete Everything Inside

You may encounter:

rm -rf folder/


Breakdown:

-r → Recursive
     Delete everything inside

-f → Force
     Don't ask for confirmation


So:

rm -rf folder/


can delete the directory and all its contents.

⚠️ This command can cause serious data loss.

════════════════════════════════════

🎯 Interview Revision

* `touch` → Create an empty file / update timestamp.
* `cp` → Copy files.
* `cp -r` → Copy directories recursively.
* `mv` → Move or rename files/directories.
* `rm` → Delete files.
* `rmdir` → Delete an empty directory.
* `rm -rf` → Recursively and forcefully delete a directory and its contents.
* Best Practice → Check pwd and ls before deleting anything.

## 📄 `cat` → Read the Entire File

For a small file:

It prints the entire contents to the terminal.

Good for:

📄 Small files

↑ / ↓  → Move

## ⬆️ `head` → See the Beginning

You can specify the number of lines:

💼 Useful for checking application startup information.

════════════════════════════════════

## ⬇️ `tail` → See the Latest Entries

Production issues are often in the most recent log entries.

Use:

tail application.log


By default, it shows the last 10 lines.

Latest log entries
        ↓
   tail
        ↓
See what happened recently


════════════════════════════════════

## 🔥 `tail -f` → Watch Logs Live

This is one of the most useful commands for production troubleshooting.

tail -f application.log


-f means:

> Follow the file.

The terminal stays open and displays new log entries as the application writes them.

Example:

10:01 Application Started
10:02 Database Connected
10:03 User Login
10:04 Payment Request
10:05 ERROR: Database Connection Refused


You don't need to reopen the file.

Think of it as a live CCTV camera for your application logs. 📺

Press:

Ctrl + C


to stop following the file.

════════════════════════════════════

## 🔐 Permissions

There are 3 basic permissions:

r → Read
w → Write
x → Execute


And they apply to:

Owner | Group | Others


Example:

-rwxr-xr--


means:

Owner  → rwx
Group  → r-x
Others → r--


════════════════════════════════════

## 🔢 Permission Numbers

Linux represents permissions using numbers:

r = 4
w = 2
x = 1


So:

rwx = 4+2+1 = 7

r-x = 4+1   = 5

r-- = 4      = 4


Therefore:

755

↓

rwxr-xr-x


Common permissions:

755 → Executable files/scripts

644 → Normal/configuration files

600 → Private files

777 → Everyone has full access ⚠️


════════════════════════════════════

## ⚙️ `chmod` — Change Permissions

Make a script executable:

chmod +x deploy.sh


Or:

chmod 755 deploy.sh


Then:

can execute successfully.

* `chmod` → Change permissions.
* `chown` → Change ownership.
* 755 → rwxr-xr-x
* 644 → rw-r--r--
* 600 → rw-------
* `-R` → Recursive.

Port 22

Server → 43.205.xx.xx

User   → ubuntu

🚀 Part 12: Cron Jobs - Automating Tasks in Linux

════════════════════════════════════

## 🤔 What Is Cron?

Cron is a Linux scheduler that automatically runs commands/scripts at specified times.

Think:

You schedule a task
       ↓
cron waits
       ↓
Time arrives
       ↓
Command runs automatically


Common uses:

* Database backups
* Log cleanup
* Reports
* Health checks
* File synchronization

════════════════════════════════════

## 📋 Cron Commands

View your cron jobs:

crontab -l


Create/edit cron jobs:

crontab -e


════════════════════════════════════

## 🧩 Cron Syntax

* * * * * command
│ │ │ │ │
│ │ │ │ └── Day of Week
│ │ │ └──── Month
│ │ └────── Day of Month
│ └──────── Hour
└────────── Minute


Remember:

Minute → Hour → Day → Month → Day of Week


════════════════════════════════════

## ⭐️ Important Examples

### Every day at 2 AM

0 2 * * * /opt/scripts/backup.sh


Meaning:

Every day
at 02:00
run backup.sh


### Every 10 minutes

*/10 * * * * /opt/scripts/health-check.sh


### Every Monday at 9 AM

0 9 * * 1 /opt/scripts/report.sh


### Every day at 1 AM

0 1 * * * /opt/scripts/cleanup.sh


════════════════════════════════════

## 💼 Real Project: PostgreSQL Backup

Create:

/opt/scripts/backup.sh


Then schedule:

0 2 * * * /opt/scripts/backup.sh


Flow:

2:00 AM
   ↓
cron
   ↓
backup.sh
   ↓
PostgreSQL Backup
   ↓
Backup File


Nobody needs to log in manually.

════════════════════════════════════

## 📁 Where Should Scripts Go?

A common approach is:

/opt/scripts/

├── backup.sh
├── cleanup.sh
└── health-check.sh


Then cron runs the script:

0 2 * * * /opt/scripts/backup.sh


Using absolute paths is recommended.

════════════════════════════════════

## ⚠️ Important Cron Considerations

Cron runs with a minimal environment.

So don't assume it has the same PATH, environment variables, or working directory as your terminal.

Prefer:

/opt/scripts/backup.sh


instead of:

backup.sh


Also make the script executable:

chmod +x /opt/scripts/backup.sh


Test the script manually before scheduling it.

════════════════════════════════════

## 📝 Logging Cron Output

You can redirect output to a log:

0 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1


Meaning:

>> backup.log
    ↓
Append normal output

2>&1
    ↓
Also send errors to the same log


This makes troubleshooting much easier.

════════════════════════════════════

## 🧠 Memory Trick

crontab
   ↓
Schedule
   ↓
cron waits
   ↓
Time arrives
   ↓
Command executes


Think:

> Cron = Alarm clock for Linux commands.

════════════════════════════════════

* `crontab -l` → List cron jobs.
* `crontab -e` → Edit cron jobs.
* Cron format → Minute Hour Day Month DayOfWeek Command
* `*` → Every value.
* `*/10` → Every 10 units.
* `0 2 * * *` → Every day at 2 AM.
* Best Practice → Use scripts + absolute paths + logging.

🚀 Part 13: Package Management - APT

════════════════════════════════════

## 🤔 What is a Package Manager?

A package manager installs and manages software on Linux.

Think:

Package Manager
      ↓
Software Store for Linux


Instead of manually downloading software, Linux can install it from trusted repositories.

For Ubuntu/Debian, the common package manager is:

APT


APT = Advanced Package Tool

════════════════════════════════════

## 📦 Package & Repository

### Package

A package is software bundled with the files it needs.

Examples:

nginx
git
curl
postgresql
openjdk


### Repository

A repository is a trusted server containing packages.

Ubuntu Repository
        ↓
   ┌────┼────┐
   ↓    ↓    ↓
 nginx git  curl


APT downloads packages from repositories.

════════════════════════════════════

## 🔄 `apt update` vs `apt upgrade`

This is the most important concept.

### apt update

sudo apt update


Updates APT's package information/catalog.

It does NOT upgrade your installed software.

### apt upgrade

sudo apt upgrade


Actually upgrades installed packages to newer versions.

Remember:

apt update
     ↓
Refresh Catalog

apt upgrade
     ↓
Install New Versions


════════════════════════════════════

## 📥 Installing Software

sudo apt install nginx


Install multiple packages:

sudo apt install git curl vim


Search for a package:

apt search nginx


════════════════════════════════════

## 🗑 Removing Software

Remove:

sudo apt remove nginx


Remove package + configuration:

sudo apt purge nginx


Remove unused dependencies:

sudo apt autoremove


════════════════════════════════════

## 💼 Real Server Setup

For a new Ubuntu server, you might do:

sudo apt update

sudo apt upgrade

sudo apt install git

sudo apt install openjdk-17-jdk

sudo apt install nginx


Then deploy your Spring Boot application.

* Package → Bundled software.
* Repository → Server containing packages.
* `apt update` → Refresh package information.
* `apt install` → Install software.
* `apt upgrade` → Upgrade installed packages.
* `apt remove` → Remove software.
* `apt purge` → Remove software + configuration.
* `apt autoremove` → Remove unused dependencies.
