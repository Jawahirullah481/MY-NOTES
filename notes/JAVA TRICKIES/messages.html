# 🔥 Java SE – Tricky Theoretical Q & A (Part 1)

---

## 1️⃣ Can an interface have instance variables?

❌ No

An interface cannot have instance variables.

All variables inside an interface are:

public static final


Even if you don’t write it, the compiler adds it.

Example:

interface Test {
    int x = 10;
}


Actually becomes:

public static final int x = 10;


✔️ No instance variables
✔️ Only constants allowed

---

## 2️⃣ Can an interface have static variables?

✅ Yes

All variables in interface are automatically static.

interface A {
    int value = 100;  // static
}


Access using:

A.value;


---

## 3️⃣ Can an interface have constructors?

❌ No

Reason:

- Interfaces cannot be instantiated
- Constructors are used to initialize objects
- No object → No constructor

---

## 4️⃣ Can an interface have methods with body?

Depends on Java version:

Java Version    Allowed?
---------------------------------
Java 7          ❌ No
Java 8          ✅ default & static methods
Java 9+         ✅ private methods also


Example:

interface A {

    default void show() {
        System.out.println("Hello");
    }

    static void print() {
        System.out.println("Static");
    }

    private void helper() {
        System.out.println("Private");
    }
}


---

## 5️⃣ Can a class implement multiple interfaces?

✅ Yes

Java does not support multiple inheritance of classes.
But supports multiple inheritance of interfaces.

class A implements X, Y {
}


---

## 6️⃣ Can an abstract class have constructor?

✅ Yes

When a child class object is created,
Parent constructor runs first.

abstract class A {
    A() {
        System.out.println("Constructor of A");
    }
}


---

## 7️⃣ Can an abstract class have static methods?

✅ Yes

Abstract class can have:

- static methods
- final methods
- concrete methods
- abstract methods

---

## 8️⃣ Are inner classes private?

Depends.

There are 4 types:

- Member Inner Class
- Static Nested Class
- Local Inner Class
- Anonymous Inner Class

Member inner class can be:

- private
- protected
- default
- public

Example:

class Outer {
    private class Inner {
    }
}


❌ Not all inner classes are private.

---

## 9️⃣ Can we override static methods?

❌ No

Static methods are not overridden.
They are method hidden.

Reason:

- Overriding = runtime polymorphism
- Static methods use compile-time binding

---

## 🔟 Can we override private methods?

❌ No

Private methods are not inherited.
If not inherited → cannot override.

---

## 1️⃣1️⃣ Can we override final method?

❌ No

final method cannot be overridden.

---

## 1️⃣2️⃣ Can constructor be overridden?

❌ No

Constructors are not inherited → cannot override.

✅ Yes

class A {
    A() {}

✅ Yes

But JVM only calls:

public static void main(String[] args)

## 1️⃣5️⃣ Can we make class private?

Top-level class → ❌ No
Inner class → ✅ Yes

Top-level class can only be:

- public
- default

String is immutable.

# JDK, JRE, JVM — Clear Understanding

Think of Java execution in two phases:

1. Development phase → Writing & compiling code
2. Execution phase → Running the program

Different components handle these phases.

---

# 1️⃣ JDK (Java Development Kit)

JDK is the complete toolkit required to develop Java applications.

It contains:

* JRE
* Development tools

Important tools inside JDK:

Tool      | Purpose
----------|----------------------------------------------------
javac     | Compiles .java source code into .class bytecode
java      | Runs the compiled program
jar       | Creates and manages jar files
javadoc   | Generates documentation


### Role of JDK

When a developer writes a Java program:

1. Write source code (.java)
2. Use javac (from JDK) to compile it
3. Compiler produces bytecode (`.class`)

So JDK is used for development and compilation.

---

# 2️⃣ JRE (Java Runtime Environment)

JRE provides the environment required to run Java programs.

It contains:

* JVM
* Core Java libraries
* Supporting runtime files

Example libraries include packages like:

* java.lang
* java.util
* java.io

These libraries are required while running programs.

### Role of JRE

When you run a Java program:

java MyProgram


JRE provides:

* required libraries
* the JVM to execute the bytecode

So JRE is responsible for running Java programs.

---

# 3️⃣ JVM (Java Virtual Machine)

JVM is the execution engine that runs Java bytecode.

Java programs are compiled into bytecode (.class file).
This bytecode is platform independent.

JVM converts this bytecode into platform-specific machine code.

Because every OS has its own JVM implementation.

Example:

| OS      | JVM         |
| ------- | ----------- |
| Windows | Windows JVM |
| Linux   | Linux JVM   |
| Mac     | Mac JVM     |


The bytecode remains the same, but the JVM implementation differs.

This is why Java follows:

Write Once, Run Anywhere.

---

# Internal Jobs of JVM

When you run a Java program, JVM performs several tasks.

### 1️⃣ Class Loading

JVM loads the required .class files into memory using the Class Loader subsystem.

Example:

* Bootstrap class loader
* Extension class loader
* Application class loader

---

### 2️⃣ Bytecode Verification

Before executing the code, JVM verifies the bytecode to ensure:

* it follows Java rules
* no illegal memory access
* no corrupted bytecode

This improves security and reliability.

---

### 3️⃣ Memory Management

JVM manages memory areas such as:

* Heap → Objects
* Stack → Method calls, local variables
* Method Area → Class metadata
* Program Counter Register

---

### 4️⃣ Execution Engine

The execution engine runs the bytecode using:

Interpreter

* Reads bytecode line by line
* Converts it to machine code

JIT Compiler

* Detects frequently executed code (hot code)
* Converts it to native machine code
* Stores it for reuse

This improves performance.

---

### 5️⃣ Garbage Collection

JVM automatically removes unused objects from heap memory.

This prevents memory leaks and reduces manual memory management.

---

### 6️⃣ Thread Management

JVM manages thread execution, scheduling, and synchronization.

---

# Relationship Between Them

JDK
 ├── Development tools (javac, jar, javadoc)
 └── JRE
       ├── JVM
       └── Core Java Libraries


---

# Simple Analogy

Think of it like building and running a car.

| Component | Analogy                               |
| --------- | ------------------------------------- |
| JDK       | Full car factory (tools to build car) |
| JRE       | Garage to run the car                 |
| JVM       | Engine that actually runs the car     |


---

# Short Summary

* JDK → Development kit (compile + run)
* JRE → Runtime environment (libraries + JVM)
* JVM → Engine that executes bytecode

Preparation (The JVM's Workspace):
When the JVM starts, it asks the OS for a large chunk of RAM (the Heap and the Code Cache). The OS grants this and marks specific areas as "Executable."

Conversion (Bytecode → Machine Code):
The JIT Compiler takes your Java bytecode and translates it into native machine code. It writes this machine code directly into that "Executable" area of the RAM (the Code Cache).

The Hand-off (The Instruction Pointer):
The JVM is already a process running on the CPU. To run your compiled Java code, the JVM executes a "Jump" instruction. This tells the CPU: "Stop reading the JVM's management code and start reading the instructions starting at RAM Address X."

The Execution (CPU & OS):
The CPU begins pulling those 1s and 0s from the RAM and processing them. The OS sits in the background, making sure the JVM doesn't try to access memory it doesn't own.

OOPS Concept :

---

## 1. Encapsulation

Definition: The bundling of data (variables) and methods that operate on that data into a single unit (class) while hiding the internal state from the outside world.

* The Goal: Data Integrity and Security.
* Real-World Library Example: `java.util.ArrayList`
* The Hidden Data: The ArrayList has a private array Object[] elementData.
* The Protection: You cannot touch that array. You use add() or remove(). If the array is full, the ArrayList automatically grows it behind the scenes. Because it is encapsulated, you don't have to worry about the array's size—it "just works."



---

## 2. Abstraction

Definition: Hiding the complex implementation details and showing only the essential features (the "what" instead of the "how") to the user.

* The Goal: Reducing Complexity.
* Real-World Library Example: `java.sql.Connection` (JDBC)
* The Concept: When you connect to a database in Java, you use the Connection interface.
* The Reality: Whether you are connecting to MySQL, PostgreSQL, or Oracle, the code you write looks exactly the same (connection.createStatement()).
* How it works: You don't care *how* MySQL sends packets over the network vs. how Oracle does it. You only care about the "Abstract" idea of a connection.



---

## 3. Inheritance

Definition: A mechanism where one class (child/subclass) acquires the properties and behaviors of another class (parent/superclass).

* The Goal: Code Reusability.
* Real-World Library Example: `java.io.InputStream`
* The Parent: InputStream defines basic behavior like read() and close().
* The Children: FileInputStream (for files), ByteArrayInputStream (for memory), and SocketInputStream (for networks) all inherit from it.
* The Benefit: You can write a single method that accepts an InputStream, and it will work for files, networks, or strings without changing a single line of code.



---

## 4. Polymorphism

Definition: The ability of an object to take on many forms. In Java, this usually means a parent class reference pointing to a child class object.

* The Goal: Flexibility and Extensibility.
* Real-World Library Example: `java.util.List` interface
* The Many Forms: 
List<String> list1 = new ArrayList<>();
List<String> list2 = new LinkedList<>();


```


* The Magic: You can call list1.add() and list2.add(). Even though the logic inside an ArrayList (array-based) is totally different from a LinkedList (node-based), your code treats them both as a "List." This is Dynamic Polymorphism (Method Overriding).



---

### Quick Comparison Table

Concept         | Keyword     | Focus        | Analogy
--------------- | ----------- | ------------ | -------------------------------------------------------------
Encapsulation   | private     | Protection   | A Capsule (hides the medicine inside)
Abstraction     | interface   | Simplicity   | A TV Remote (you press "Power," you don't see the circuit board)
Inheritance     | extends     | Reusability  | Family DNA (getting traits from parents)
Polymorphism    | implements  | Flexibility  | A Smartphone (one device that acts as a camera, phone, and map)


---

### How they work together in a Project

Imagine you are building a Payment System:

1. Encapsulation: Hide the creditCardNumber and cvv in a Payment class.
2. Abstraction: Create a PaymentProcessor interface with a process() method.
3. Inheritance: Create StripeProcessor and PayPalProcessor that inherit from a base BaseProcessor.
4. Polymorphism: Your main code just says processor.process(payment), and it works regardless of whether the user chose Stripe or PayPal.

Since you've been working with Java Streams and SQL, would you like to see how these OOP concepts make the Streams API or JDBC so easy to use?

Storage of String in Memory :

---

### Code

String s1 = "Jawa"; // L1
String s2 = "Jawa"; // L2
String s3 = new String("Jawa"); // L3
String s4 = new String("Kamal"); // L4


---

# L1

When this line executes:

String s1 = "Jawa";


* "Jawa" is a string literal
* JVM checks the String Constant Pool (SCP)
* Since it does not exist yet, it creates a String object in SCP
* s1 (stored in stack) holds the reference to that object.

---

# L2

String s2 = "Jawa";


* JVM again checks the String Constant Pool
* "Jawa" already exists
* No new object is created
* s2 references the same object in SCP

---

# L3

String s3 = new String("Jawa");


Steps:

1. JVM checks SCP for "Jawa"
2. "Jawa" already exists in SCP, so no new literal is created
3. new String() always creates a new object in heap memory
4. s3 points to this new heap object

So now there are:

* one object in SCP
* one object in heap

---

# L4

String s4 = new String("Kamal");


Steps:

1. JVM checks SCP for "Kamal"
2. Since it does not exist, it creates "Kamal" in SCP
3. Because new is used, another new String object is created in heap
4. s4 points to the heap object

---

# Final Memory State

Stack                 Heap

s1 ──┐
     │
s2 ──┘        "Jawa" (String Constant Pool)

s3 ─────────> new String("Jawa")

s4 ─────────> new String("Kamal")

              "Kamal" (String Constant Pool)


---

# Important Behavior

s1 == s2      → true
s1 == s3      → false
s1.equals(s3) → true


* == compares references
* equals() compares content.

# HashMap Internal Working (Important Interview Topic)

## 1. Hashing

Hashing is the technique used by HashMap to store and retrieve data efficiently.

When you insert a key-value pair:

map.put(key, value);


Java performs:

1. Calls key.hashCode()
2. Converts hashcode to array index
3. Stores entry in that position (bucket)

Example:

hashCode("CAT") → 12345
index = 12345 % arraySize


So the object is stored in:

table[index]


This is why HashMap average time complexity = O(1).

---

# 2. Buckets

The internal structure of HashMap is:

Node<K,V>[] table


This is simply an array.

Each array position is called a Bucket.

Example:

Index     Bucket
0         -
1         Node
2         Node -> Node
3         -
4         Node


Each bucket can contain:

* Single Node
* Linked List
* Red-Black Tree (Java 8+)

Node structure:

class Node<K,V> {
    int hash;
    K key;
    V value;
    Node next;
}


---

# 3. Collision Handling

A collision happens when two keys generate the same bucket index.

Example:

hashCode("CAT") → index 3
hashCode("DOG") → index 3


Both go to the same bucket.

Then Java stores them as a Linked List.

Bucket[3]

CAT -> DOG -> ELEPHANT


When retrieving:

map.get("DOG")


Java:

1. Finds bucket using hash
2. Traverses list
3. Uses equals() to match key

So worst case becomes:

O(n)


---

# 4. Treeification (Java 8 Improvement)

Before Java 8:

Collision → Linked List


If many collisions occur:

O(n)


To improve performance, Java 8 introduced Treeification.

### Rule

If bucket size > 8

Linked List converts into Red-Black Tree

Bucket

Before:
A → B → C → D → E → F → G → H → I

After:
      D
     / \
    B   F
   / \ / \
  A  C E  G
           \
            H
             \
              I


Now search becomes:

O(log n)


---

# Treeification happens only when BOTH conditions are true

Bucket size > 8
AND
HashMap capacity ≥ 64


Otherwise Java will resize the HashMap instead.

---

# 5. HashMap Resizing (Rehashing)

Default capacity:

16


Default load factor:

0.75


Threshold:

capacity * loadFactor
16 * 0.75 = 12


When entries exceed 12, HashMap doubles the size.

16 → 32 → 64 → 128


Then all elements are rehashed and redistributed.

---

# Final Interview Summary

| Concept            | Explanation                                 |
| ------------------ | ------------------------------------------- |
| Hashing            | Converts key to array index                 |
| Bucket             | Array position storing nodes                |
| Collision          | Multiple keys mapped to same index          |
| Collision Handling | Linked List                                 |
| Treeification      | Linked List → Red Black Tree when > 8 nodes |
| Default Capacity   | 16                                          |
| Load Factor        | 0.75                                        |
| Resize             | Capacity doubles when threshold exceeded    |
| Average Complexity | O(1)                                        |
| Worst Case         | O(log n) (after Java 8)                     |


---

# One Important Interview Question

Why is HashMap faster than TreeMap?

Answer:

HashMap → O(1) average (hashing)
TreeMap → O(log n) (Red Black Tree)


So HashMap is faster for most operations.

Generics :

---

# 1. Why Generics Were Introduced

Before Java 5:

List list = new ArrayList();
list.add("Java");
list.add(10);


Problem:

* No type safety
* Need type casting when reading

String s = (String) list.get(0);


Generics solve this.

List<String> list = new ArrayList<>();
list.add("Java");


Now:

* Only String allowed
* No casting required
* Compile-time safety

---

# 2. Generic Class

A generic class works with different types.

class Box<T> {
    T value;

    void set(T value){
        this.value = value;
    }

    T get(){
        return value;
    }
}


Usage:

Box<Integer> b1 = new Box<>();
Box<String> b2 = new Box<>();


Here:

T → Type Parameter


---

# 3. Generic Method

Generics can be used in methods also.

public <T> void print(T value){
    System.out.println(value);
}


Usage:

print("Java");
print(10);


Note:

<T>


must appear before return type.

---

# 4. Bounded Generics

Sometimes we restrict types.

Example:

<T extends Number>


Meaning:

T can be:
Integer
Double
Float
Long
etc


Example:

class Calculator<T extends Number> {
    T num;
}


---

# 5. Wildcards

Wildcards represent unknown type.

Symbol:

?


Example:

List<?> list


Meaning:

List of unknown type


---

# 6. Types of Wildcards

## 1️⃣ Unbounded Wildcard

List<?> list


Accepts:

List<String>
List<Integer>
List<Double>


But:

list.add("Java") ❌


Because type is unknown.

Only safe operation:

Object obj = list.get(0);


---

# 2️⃣ Upper Bounded Wildcard

List<? extends Number>


Accepts:

List<Integer>
List<Double>
List<Float>


But NOT:

List<String>


Important rule:

Can READ
Cannot ADD


Example:

Number n = list.get(0);  // OK
list.add(10);            // ❌


Why?

Compiler doesn't know exact subtype.

---

# 3️⃣ Lower Bounded Wildcard

List<? super Integer>


Accepts:

List<Integer>
List<Number>
List<Object>


Important rule:

Can ADD
Cannot safely READ


Example:

list.add(10);     // OK
Object obj = list.get(0); // Only Object


---

# 7. Golden Rule (Very Important)

This is the PECS Rule.

Producer → Extends
Consumer → Super


Meaning:

| Situation                            | Use       |
| ------------------------------------ | --------- |
| If you only **read from collection** | `extends` |
| If you only **add to collection**    | `super`   |


Example:

Read numbers:

List<? extends Number>


Add numbers:

List<? super Integer>


---

# 8. Generic vs Wildcard (Major Confusion)

### Generic Type

Used when defining relationship between types

Example:

class Box<T>


or

<T> void print(T value)


---

### Wildcard

Used when method accepts multiple generic types

Example:

void printList(List<?> list)


---

# 9. When to Use Generics vs Wildcards

### Use Generic Type

When type must remain consistent

Example:

<T> T getValue(T value)


Input and output same type.

---

### Use Wildcards

When method just works with collection

Example:

void printList(List<?> list)


Works for any list.

---

# 10. Very Important Interview Example

Why this is wrong:

List<Object> list = new ArrayList<String>(); ❌


Because:

Generics are invariant


Correct way:

List<?> list = new ArrayList<String>(); ✅


---

# 11. Type Erasure (Important Interview Topic)

Generics exist only at compile time.

During compilation:

List<String>


becomes

List


So runtime JVM does not know generic type.

This is called:

Type Erasure


---

# 12. Small Cheat Sheet (Best for Your Notes)

| Syntax          | Meaning                |
| --------------- | ---------------------- |
| `<T>`           | Generic type parameter |
| `<?>`           | Unknown type           |
| `<? extends T>` | Upper bound            |
| `<? super T>`   | Lower bound            |

# Final Interview Trick

Remember this one sentence:

extends → read
super → write


Or better:

PECS

# 2️⃣ Question 2 — What Can Be Added?

Which are allowed?

list.add(10);
list.add(5.5);

### ✅ Correct Answer

Only this works:

Because the compiler doesn't know the exact subtype.

It could be:

List<Integer>
List<Double>

# 1️⃣ Can we submit different types of tasks to the same ExecutorService?

✅ Yes.

An ExecutorService is just a thread pool that executes tasks.
It does not care what the task logic is.

You can submit:

* Runnable task B
* Callable task C
* Callable task D

All to the same executor.

executor.submit(() -> System.out.println("Task 2"));

    System.out.println("Task 3 result: " + sum);
});


All different tasks run using the same thread pool.

# 2️⃣ Do we need to call submit() every time to start a new task?

✅ Yes.

Each call to submit() adds a new task to the executor queue.

Example:

executor.submit(task1);
executor.submit(task2);
executor.submit(task3);


Flow:

submit(task1) → task queue
submit(task2) → task queue
submit(task3) → task queue


Worker threads will pick tasks from the queue and execute them.

| Access outer static members   | ✅ Yes               | ✅ Yes               |
| Memory usage                  | More                | Less                |
| Object creation               | `outer.new Inner()` | `new Outer.Inner()` |


---

# Accessibility Rules

| Outer Member | Member Inner Class | Static Inner Class |
| ------------ | ------------------ | ------------------ |
| Private      | ✅ Accessible       | ❌ Not directly     |
| Static       | ✅ Accessible       | ✅ Accessible       |
| Instance     | ✅ Accessible       | ❌ Not accessible   |


---

# Why Static Inner Classes Exist

They are used when the inner class does not need outer object data.

Example: Helper classes.

Example in Java library:

* Map.Entry
* Thread.State

# Reflection API (Java)

## 1. What is Reflection?

Reflection API allows a Java program to examine and manipulate its own structure at runtime.

Using reflection we can:

* Inspect classes
* Access fields
* Call methods
* Create objects dynamically

Even if they are private.

---

# 2. Why Reflection is Used

Reflection is heavily used in frameworks such as:

* Spring Framework
* Hibernate
* JUnit

Because frameworks don't know your classes at compile time, they discover them at runtime using reflection.

Example:

Class.forName("com.app.UserService")


---

# 3. Important Classes in Reflection

| Class         | Purpose                              |
| ------------- | ------------------------------------ |
| `Class`       | Represents class metadata            |
| `Field`       | Represents class variables           |
| `Method`      | Represents class methods             |
| `Constructor` | Represents constructors              |
| `Modifier`    | Checks modifiers like public/private |


Package:

java.lang.reflect


---

# 4. Getting Class Object

There are 3 ways.

### Method 1

Class c = Class.forName("User");


Loads class dynamically.

---

### Method 2

User u = new User();
Class c = u.getClass();


---

### Method 3

Class c = User.class;


Most commonly used.

---

# 5. Getting Class Information

Example class:

class User {
    private int id;
    public String name;

    public void show() {}
}


### Get fields

Field[] fields = User.class.getDeclaredFields();


---

### Get methods

Method[] methods = User.class.getDeclaredMethods();


---

### Get constructors

Constructor[] constructors = User.class.getDeclaredConstructors();


---

# 6. Accessing Private Fields

Normally this is not allowed.

Reflection allows it.

Field field = User.class.getDeclaredField("id");

field.setAccessible(true);

User u = new User();
field.set(u, 10);

System.out.println(field.get(u));


---

# 7. Invoking Methods Dynamically

Method m = User.class.getDeclaredMethod("show");

User u = new User();

m.invoke(u);


This calls:

u.show();


---

# 8. Creating Object Using Reflection

Instead of:

User u = new User();


We can do:

Class c = User.class;

User u = (User) c.getDeclaredConstructor().newInstance();


---

# 9. Getting Method Parameters

Example:

Method m = User.class.getDeclaredMethod("add", int.class, int.class);


Invoke:

Object result = m.invoke(obj, 10, 20);


---

# 10. Advantages

| Advantage            | Explanation                   |
| -------------------- | ----------------------------- |
| Dynamic execution    | Classes discovered at runtime |
| Framework building   | Used in Spring, Hibernate     |
| Testing tools        | Used in JUnit                 |
| Dependency Injection | Core mechanism                |

---

# 11. Disadvantages

| Disadvantage         | Reason                     |
| -------------------- | -------------------------- |
| Slow performance     | Runtime inspection         |
| Breaks encapsulation | Can access private members |
| Hard to debug        | Dynamic behavior           |


---

Framework code:

Class<?> clazz = Class.forName("com.app.Service");

Object obj = clazz.getDeclaredConstructor().newInstance();

Method method = clazz.getMethod("execute");

method.invoke(obj);


Framework doesn't know the class at compile time.

# Java Lambda, Functional Interface & Method Reference

---

# 1. Functional Interface

### Definition

A Functional Interface is an interface that contains exactly one abstract method.

It can have:

* multiple default methods
* multiple static methods

But only one abstract method.

### Example

@FunctionalInterface
interface Greeting {
    void sayHello(String name);
}


### Common Built-in Functional Interfaces

| Interface  | Abstract Method |
| ---------- | --------------- |
| Runnable   | run()           |
| Comparator | compare()       |
| Callable   | call()          |
| Consumer   | accept()        |
| Supplier   | get()           |
| Function   | apply()         |
| Predicate  | test()          |


Example:

Runnable r = () -> System.out.println("Running");


---

# 2. Lambda Expression

### Definition

A Lambda Expression is a short way to implement the abstract method of a functional interface.

### Syntax

(parameters) -> { body }


### Example

Functional Interface

interface Printer {
    void print(String s);
}


Lambda implementation

Printer p = s -> System.out.println(s);


Equivalent old style:

Printer p = new Printer() {
    public void print(String s) {
        System.out.println(s);
    }
};


### Key Points

* Lambda can only work with Functional Interfaces
* It implements the single abstract method
* Java infers the type automatically

Example

Comparator<Integer> c = (a,b) -> a - b;


---

# 3. Method Reference

### Definition

A Method Reference is a shorter version of lambda when the lambda only calls an existing method.

### Lambda

list.forEach(x -> System.out.println(x));


### Method Reference

list.forEach(System.out::println);


Meaning:

System.out.println(x)


---

# 4. Types of Method References

### 1️⃣ Static Method Reference

ClassName::staticMethod


Example

Integer::parseInt


Lambda equivalent

s -> Integer.parseInt(s)


---

### 2️⃣ Instance Method of Particular Object

object::method


Example

System.out::println


Lambda equivalent

x -> System.out.println(x)


---

### 3️⃣ Instance Method of Arbitrary Object

ClassName::method


Example

String::toUpperCase


Lambda equivalent

s -> s.toUpperCase()


---

### 4️⃣ Constructor Reference

ClassName::new


Example

Supplier<List<String>> list = ArrayList::new;


Lambda equivalent

Supplier<List<String>> list = () -> new ArrayList<>();


---

# Relationship Between Them

Functional Interface → Lambda Expression → Method Reference
      Target              Implementation        Shortcut


Example

### Functional Interface

interface Printer {
    void print(String s);
}


### Lambda

Printer p = s -> System.out.println(s);


### Method Reference

Printer p = System.out::println;


---

# Important Rules

### Rule 1

Lambda requires a Functional Interface.

### Rule 2

Method Reference works only when lambda calls a single method.

### Rule 3

Lambda implements the abstract method.

---

# Quick Memory Trick

Remember this chain:

Anonymous Class → Lambda → Method Reference
   Long code        Short        Shortest


Example

Anonymous class

list.forEach(new Consumer<String>() {
    public void accept(String s) {
        System.out.println(s);
    }
});


Lambda

list.forEach(s -> System.out.println(s));


Method reference

list.forEach(System.out::println);
