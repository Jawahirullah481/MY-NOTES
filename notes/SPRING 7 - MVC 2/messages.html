Spring MVC Tutorial :
==============

Steps to configure Spring MVC :
=====================

1. Create maven project and add spring context, spring MVC dependencies.
2. Create <servlet> tag for Dispatcher servlet.
3. So, we have to create separate spring configuration file with name of "dispatcher-servlet.xml".
4. In that configuration file, we have to define controllers or we have use <context:component-scan> to create bean.
5. Create @Controller and @RequestMapping.
6. Create bean for "InternalResourceViewResolver" with "prefix" and "suffix" properties.
7. Create view pages under "WEB-INF" folder.

NOTE :
i) An important point is we have to create src/main/java folder in spring mvc application. maven doesn't create us that folder. Don't forget to do this.

How Dispatcher Servlet Works :
=====================
1. Dispatcher servlet is also called frontcontroller.
2. When request comes to web server, as it is dynamic request, it sends to web container.
3. Web container looks web.xml file and forward the request to DispatcherServlet.
4. DispatcherServlet forward to handler.
5. Handler looks Bean objects in spring container.
6. As we use <context:component-scan> and all @Controller will be created as bean.
7. Then url-patterns are matched using @RequestMapping annotation. Then that particular request handler method in executed and it returns the "View page file name" or "ModelAndView" Object to DispatcherServlet.
8. DispatcherServlet seeks help of ViewResolver to find the correct physical location of the view file.
9. Then it returns the view file with providing the model information.

</servlet>

@PathVariable :
===========
# In the Normal web applications, parameters are passed in query string. Example : "typerace.com/rank=2&points=4".
In this scenaria, to get parameters we use @RequestParam annotations.

# In the Restful web applications, parameters are passed in following pattern. Example : "typeracer.com/2/4". There is no query string. In this scenario we use "@PathVariable".
To use this annotation, we have to mention the param names in @RequestMapping url pattern.

Example :
@RequestMapping("typerace.com/{rank}/{points}")
public String method(@PathVariable("rank") int rank, @PathVariable("points") int points) {}

Using Map to catch @RequestParams and @PathVariables :
=======================================
Suppose if you have more number of request parameters, you can put them in a single map, instead of use separate @RequestParam or @PathVariable for each paramter.

Example :
=======

int num2 = map.get("num2");
}

📌NOTE : Here the parameter names and their values are stored in form of map.

RequestDispatcher.forward() and Response.sendRedirect() :
==================================================
# If you want to forward the request to another url or page, make the request handler method return the following string.
return "forward:/<url-pattern>"
# If you want to redirect the request to another url or page, make the request handler method return the following string.
return "redirect:/<url-pattern>".

Example :
========
@RequestMapping("/x")
public String abc() {
return "redirect:/y";
}

@RequestMapping("/y")
public String def() {
return "forward:/view";
}

Bean Validation in spring :
======================

During, automatic binding of the Bean object, we have to use validation. For that we have hibernate validator.

Step 1 : We have to add hibernate validator dependency.
Step 2 : We have set of annotations for bean validations. So, we have to add that annotations for POJO's properties.

Step 3 : And inside those annotations, we have one attribute called "message". Here we can specify the error message.
Step 4 : At Last add <form:error> tag after every <form:input> tag in jsp file inside spring form.
Step 5 : Now automatically the error messages will print on our web page.

By this hibernate validator and annotations, we can do spring bean validation.

In the above tutorial, we mention error messages for each bean property in message attribute.
But, There is the most recommended way is "mention all the error messages for bean validation inside separate properties file".

# Create message.properties file under /WEB-INF folder.
# Add every error message in the following format.
<Annotation-name>.<modal-attribute-name>.<bean's property name>=<message you want to print>
# Create bean for "ReloadableResourceBundleMessageSource" class using xml configuration with id = "messageSource".
# Add basename = "/WEB-INF/<filename>".

Example :
========
message.properties
——————————
NotEmpty.user.email=Email can't be empty
Email.user.email=Enter valid email address
NotNull.user.age=Age can't be empty

dispatcher-servlet.xml
——————————-
<bean id="messageSource" class="org.springframework.context.support.ReloadableResourceBundleMessageSource">
<property name="basename" value="/WEB-INF/messages"></property>
</bean>

Custom Bean Validation :
=====================
Step 1 : Create Annotation and add required attributes and also add groups and payload.
Step 2 : Add @Documented, @Retention, @Target.
Step 3 : Create class which extends Constraint Validator.
Step 4: Override initialize() to initialize annotation variable. Override isValid() and write validation Logic.
Step 5 : Add Custom Annotation in the Bean Class.

Example :
========

Voter.java
—————
public class Voter {

@Age(min = 18, max = 60)
private int age;

//getter and setter
}

=========================

Age.java
————
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@Constraint(validatedBy = AgeValidator.class)
public @interface Age{

int min() default 0;
int max() default 0;
String message() default "Enter valid age";
Class<?>[] groups() default { };
Class<? extends Payload>[] payload() default { };

}

===========================

AgeValidator.java
————————-
public class AgeValidator implements ConstrainValidator<Age, Integer> {

int minAge;
int maxAge;

@Override
public void initialize(Age ageConstraints) {
minAge = ageConstraints.min();
maxAge = ageConstraints.max();
}

@Override
public boolean isValid(Integer age, ConstraintValidatorContext context) {
if(age < minAge || age > maxAge) {
return false;
}

return true;
}

}

@InitBinder Annotation :
=====================

By using @ModelAttribue and spring form,
i) Integer datas are bind with int type
ii) Words are bind with String type

But, how dates are bind with dates? To resolve this problem, we have @InitBinder method.

@InitBinder annotation is applicable for method. That method will be called with "WebDataBinder" argument. We have to register the custom editors into that binder for particular class and also for particular property of POJO class.

Example :
========
@InitBinder
protected void initBinder(WebDataBinder binder) {
DateFormat formatter = new SimpleDateFormat("dd/MM/yyyy");
binder.registerCustomEditor(Date.class, "dob", new CustomDateEditor(formatter, false));
}

In the above example, this method will executed when you are binding Spring form with POJO object. When the POJO object contains Date type property, then automatically thin @InitBinder method will be executed. And The user entered format is converted into DateFormat format and parse with "dob" property in POJO class.

=======================

You can also create your own Property Editor. Suppose, the user entered a string. And you want to store the data into uppercase into your object. For this you can use this custom editor. To do this,
Step 1 : Create class which extends PropertyEditorSupport
Step 2 : Override setAsText(String value) method.
Step 3 : make changes to the value and call setValue() method.
Step 4 : Register Custom Editor into WebDataBinder in @InitBinder method.

Example :
========
NameEditor.java
————————

public class NameEditor extends PropertyEditorSupport {
@Override
public void setAsText(String text) throws IllegalArgumentException {
String newName = text.toUpperCase() + " .M";
super.setValue(newName);
}
}

Controller.java
———————

@InitBinder
protected void initBinder(WebDataBinder binder) {
DateFormat formatter = new SimpleDateFormat("dd/MM/yyyy");
binder.registerCustomEditor(Date.class, "dao", new CustomDateEditor(formatter, false));
binder.registerCustomEditor(String.class, "name", new NameEditor());
 System.out.println("I am here");
}

Interceptors :
===========
This are something like Spring AOP's Aspect classes and advice method. When the particular request is processed by handler method, then this interceptor will execute.

Suppose, we have a handler method as following.

@RequestMapping("/add")
public ModelAndView add(@RequestParam("num1") int num1, @RequestParam("num2") int num2) {
S.O.P("Handler method starts to execute");
int sum = num1 + num2;
ModelAndView mv = new ModelAndView("sum");
mv.addObject("sum", sum);
S.O.P("Handler method ends");
return mv;
}

And we have 1 Interceptor class.
NOTE : If the class want to be the interceptor class, it must implements the "HandlerInterceptor" interface.

And that inteceptor class can override necessary method. For example, we overridden 3 methods. They are,
i) preHandle(); -> contains S.O.P("preHandle")
ii) postHandle(); -> contains S.O>P("postHandle")
iii) afterCompletion(); -> contains S.O.P("afterCompletion")

After that we have to register it in dispatcher-servlet.xml file as interceptor. and also create bean for it.

dispatcher-servlet.xml :
====================
<mvc:interceptors>
<mvc:interceptor>
<mvc:mapping path="/home"/>
<bean class="com.jawa.controller.UserInterceptor"></bean>
</mvc:interceptor>
</mvc:interceptors>

Then, the output will be :
preHandle
handler method starts to execute
Handler method ends
postHandle
afterCompletion

Internalization(I18N) and Localization(L10N) :
==========================
In spring, we have a concept of Localization and Internalization. With this, we can provide user's native languages in web application.

To provide this, follow following steps :
——————————————————-
1. Create jsp page.
2. Add spring tags uri.
3. Add spring message tag with code attribute.
4. Create messages_languagecode.properties file for each language.
5. Add messages with key value pair.
6. Create interceptor with bean for "LocaleChangeInterceptor" in the dispatcher-servlet.xml with property name "paramName". Whose value is the parameter key to hold the language code.
7. Create bean for CookieLocaleResolver in dispatcher-servlet.xml file and also add required properties.

@ErrorHandler :
==============
This method will be execute when the appropriate exception arise. It can either the controller level or globel level.

Example:
=======
@Controller
public class ControllerA {
@ExceptionHandler(value = RuntimeException.class)
public String hi() {
return "runtimeexception";
}

In the above example, Whenever RuntimeException rised inside the ControllerA, then the method "hi()" will be executed, which returns the view which has userfriendly error message.

============================

You can also Specify ExceptionHandler method commonly for all the controllers in the application. To resolve this problem, we have @ControllerAdvice.

This @ContollerAdvice annotation is applicable to class. You can specify lot of @ExceptionHandler methods inside this @ControllerAdvice class whose @ExceptionHandler methods are suitable for all the @Controller classes.
